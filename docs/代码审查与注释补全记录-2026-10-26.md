### [MAJOR] 连接失败路径未确定性关闭新建通道

**文件：** backend/src/main/java/dev/mocklab/engine/RunnerClient.java

**行号：** 81-87，open 方法

**代码片段：**

```java
SocketChannel channel = SocketChannel.open();
channel.socket().connect(new InetSocketAddress(parts[0], Integer.parseInt(parts[1])), 1000);
return channel;
```

Unix Socket 分支具有相同的创建后再连接结构

**问题：** open 内创建了通道，但连接抛出异常时尚未返回，外层 try-with-resources 无法取得并关闭该对象

**影响：** runner 反复不可达或健康检查持续失败时，通道依赖后续回收而非确定性关闭，可能累积系统资源

**建议修复：** 仅在连接失败分支关闭当前新建通道并继续抛出原异常，正常连接的关闭权仍交给 invoke。无需新增重试、锁或通用连接执行器

### [MAJOR] 脚本通信异常转换时丢失内部原因

**文件：** backend/src/main/java/dev/mocklab/engine/RunnerClient.java

**行号：** 46-47，invoke 方法

**代码片段：**

```java
} catch (Exception ex) {
    throw new BusinessException(503, "MOCK_SERVICE_UNAVAILABLE", "脚本执行服务不可用");
}
```

**问题：** 各种连接、超时和协议解析失败都转换为同一业务异常，既未记录原异常也未保留 cause

**影响：** 对外统一提示是合理的，但内部无法根据日志区分地址错误、连接拒绝、响应解析失败等原因，排障信息不足

**建议修复：** 保持既有对外状态和文案，在原边界记录带堆栈的基础设施错误，或通过统一异常构造器保留 cause；不输出脚本正文、请求报文和数据库凭证
