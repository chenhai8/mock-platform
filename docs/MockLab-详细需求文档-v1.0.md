## 1. 背景与目标

### 1.1 业务背景

业务系统开发和联调经常依赖 ERP、WMS、MES 或其他第三方系统。第三方接口可能尚未交付、测试环境不可用，或者难以稳定复现异常响应。现有公网 Mock 地址无法满足公司内网服务器的网络访问和信任要求。

需要在公司内网部署独立 Mock 平台，由使用者自行配置接口路径、请求方法和响应内容，使业务服务器能够直接调用内网地址完成联调。

### 1.2 产品目标

1. 不编写后端业务代码，即可配置一个可调用的 HTTP 接口
2. 粘贴第三方报文即可按原样返回，不增加平台统一响应包装
3. 使用简单 JavaScript 函数，根据请求参数动态产生响应
4. 在同一接口下配置成功、失败、默认等响应场景
5. 通过在线调试、发布历史和调用记录定位配置问题
6. 部署后运行不依赖公网、CDN 或在线脚本库
7. 首版控制复杂度，围绕模拟第三方系统开展功能建设

### 1.3 已确认的产品决策

| 编号 | 决策 |
| --- | --- |
| D-01 | 沿用已认可的原型布局和主要使用流程 |
| D-02 | JavaScript 采用 `function main(request, mock)`，通过返回对象描述 HTTP 响应 |
| D-03 | 不兼容 Apifox 脚本对象，不提供 `$$.mockRequest`、`$$.mockResponse` |
| D-04 | 首版免登录，不建设用户、角色、项目成员和权限体系 |
| D-05 | Windows 域账号免密登录仅作为后续可选扩展，不阻塞首版 |
| D-06 | 独立项目，不依赖 pack-mom，不使用其 `PackCollectionUtils`、`EnableDto` 等项目专属类型 |
| D-07 | 优先使用 JDK、Spring 和适用公共组件，按需引入 Apache Commons 等依赖，不将“common3.2”直接视为指定组件或版本 |
| D-08 | 保留系统路径前缀，按第三方系统隔离同名接口 |

## 2. 使用者与典型场景

首版不区分产品内角色。能访问管理入口的内网使用者可以维护配置，因此部署时必须限定管理入口的网络可达范围，不能将其直接公开到互联网。

| 场景 | 使用方式 | 预期结果 |
| --- | --- | --- |
| 第三方接口未开发 | 建立接口并粘贴成功报文 | 调用方提前完成开发联调 |
| 第三方环境不可用 | 将调用方接口基础地址切换到 Mock 系统地址 | 不依赖第三方环境继续测试 |
| 模拟业务失败 | 为特定订单号设置失败场景 | 稳定复现第三方业务错误 |
| 返回值关联请求 | 脚本读取请求订单号并写入响应 | 验证请求与响应关联逻辑 |
| 模拟 HTTP 失败 | 返回 400、404、500 等状态码 | 验证调用方错误处理 |
| 模拟慢接口 | 设置响应延迟 | 验证调用方超时与重试 |
| 调整配置不影响联调 | 编辑草稿、调试后发布 | 线上调用仅使用已发布版本 |
| 配置发布错误 | 回滚到历史版本 | 恢复原有接口行为 |

## 4. 业务对象与地址规范

### 4.1 对象关系

```text
第三方系统，例如 ERP
  ├─ 接口 A：POST /api/orders/query
  │    ├─ 草稿
  │    │    ├─ 场景：订单 1001 查询成功
  │    │    ├─ 场景：订单 1002 不存在
  │    │    └─ 默认场景
  │    ├─ 不可变发布版本 v1 / v2 / v3
  │    └─ 当前发布版本指针
  └─ 接口 B：GET /api/materials/{materialId}
```

“第三方系统”是配置分组和路径命名空间，不是实际连接到该系统。首版不提供真实第三方系统连接参数。

### 4.2 HTTP 地址

```text
{mockBaseUrl}/m/{systemKey}{interfacePath}
```

例如：

```text
平台入口：http://mock.company.local
系统标识：erp
配置路径：/api/orders/query
请求方法：POST
调用地址：http://mock.company.local/m/erp/api/orders/query
```

- `mockBaseUrl` 来自部署配置，不使用浏览器当前地址或不可信 Host 头推断
- 复制地址使用实际配置的内网域名或 IP，不出现容器内部地址
- 系统标识以小写字母开头，仅允许小写字母、数字和短横线，长度 1～40
- 系统标识创建后不可修改；系统名称可修改
- 不同系统可以存在相同方法与路径，同一系统不得重复
- 未发布接口展示“待发布”，明确提示地址暂不可用
- 草稿变更路径时，分别展示草稿预览地址和当前生效地址
- 发布路径变更后，旧地址不再保留重定向或别名

## 5. 页面与交互要求

### 5.1 导航结构

左侧保留产品标识、第三方系统选择器、添加系统入口、接口管理、调用记录和使用说明。页面不出现账号头像、登录、成员管理或权限入口。

主工作区由第三方系统摘要、接口列表、接口详情组成。计数使用已保存数据，不随着尚未保存的编辑临时变化。

| 页面/区域 | 内容及操作 |

| 接口列表 | 方法、名称、路径、发布/停用状态，名称及路径搜索，分页 |

| 在线调试 | 来源选择、请求方法和路径、Query、Header、Body、发送及结果 |

### 5.3 通用交互

- 新系统没有接口时展示空状态和“新建接口”，不自动发布示例接口
- 新接口自动创建一条默认场景，初始为未发布草稿
- 输入框显示必要说明和校验提示，保存失败不得显示成功
- 有未保存修改时切换接口、系统或离开页面，提供“保存并离开 / 放弃修改 / 取消”
- 不依赖浏览器关闭事件静默保存；刷新或关闭页面前使用浏览器离开提醒
- 发布、回滚、立即停用系统和归档展示影响确认；保存草稿不需要额外确认
- 请求处理中显示状态，避免重复点击；编辑区仍可正常操作
- HTML/XML 响应按文本显示，不在后台中直接渲染用户提供的 HTML
- 错误提示指向问题字段，脚本错误显示可用的行号和简要原因
- 桌面浏览器为主要体验目标，建议 1366×768 及以上；窄屏采用折叠与纵向布局，避免控件不可访问

## 6. 系统与接口管理

### 6.1 第三方系统字段

| 字段 | 约束 |
| --- | --- |
| 名称 | 必填，去除首尾空格后 1～50 字符 |
| 系统标识 | 必填，全局唯一，包括已归档系统；符合第 4.2 节规则 |
| 说明 | 可选，最多 500 字符 |
| 启用状态 | 默认启用，但无发布接口时不可产生有效响应 |
| 归档状态 | 默认未归档 |

系统停用是立即生效的总开关，不要求逐个接口发布；停用后新请求返回平台 404。重新启用恢复原有发布状态，不自动发布任何草稿。系统归档需再次确认并立即停止新调用，默认列表隐藏，可通过归档筛选恢复。恢复后保持停用，需手动启用。首版不提供永久删除。

### 6.2 接口字段

| 字段 | 约束 |
| --- | --- |
| 名称 | 必填，1～80 字符 |
| 描述 | 可选，最多 1000 字符 |
| HTTP 方法 | GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS |
| 路径 | 必填，1～500 字符，以 `/` 开头 |
| 草稿启用状态 | 默认启用，发布后作用于真实请求 |
| 草稿修订号 | 服务端生成，用于并发修改检测 |
| 当前发布版本 | 未发布时为空 |
| 归档状态 | 默认未归档 |

路径不允许包含域名、空白、Query、片段标识、反斜杠、连续斜杠以及 `.` / `..` 路径段。首版路径模板使用 ASCII 静态段和 `{paramName}` 参数段；参数名以英文字母开头，后接字母、数字或下划线，同一模板内不可重名。不支持通配符、可选参数或正则路由。

接口复制仅复制配置为新草稿，要求填写新方法或路径，不复制发布历史和日志。复制结果不自动发布。

接口归档是立即停止新调用的操作，历史保留；恢复后仍处于未发布/不可用状态，需重新发布才能恢复调用，不能因恢复而意外开放接口。

### 6.3 路由匹配规则

1. 按系统标识查找已启用、未归档系统
2. 仅检索已发布、发布状态启用、未归档接口
3. 先匹配路径，再在选中的路径模板下匹配方法
4. 路径从左到右逐段比较，静态段优先于参数段
5. 已选中更具体路径后，不因方法不匹配而回退到更宽泛的参数路径
6. 路径无匹配返回 404；路径匹配但方法无匹配返回 405，并给出 Allow 响应头

例：`/orders/latest` 优先于 `/orders/{orderId}`。如果只配置 POST `/orders/latest`，则 GET `/orders/latest` 返回 405，不落到 GET `/orders/{orderId}`。

补充约束：

- 路径大小写敏感，`/orders` 与 `/orders/` 视为不同路径
- Query 不参与路径匹配
- 参数只匹配单个非空路径段，解码一次后放入 pathParams
- 拒绝无效百分号编码、编码的路径分隔符和编码后为点段的路径，不重复解码
- 同一方法下 `/orders/{id}` 与 `/orders/{orderId}` 视为重复，拒绝保存和发布
- 草稿和已发布路由均参与同系统冲突检查；变更路径草稿保存后暂时保留新旧路径，发布切换时释放旧路径
- HEAD 与 OPTIONS 必须显式配置，首版不隐式映射 GET，也不自动生成 Mock CORS 预检响应
- 不支持的方法返回 405；TRACE、CONNECT 不作为可配置方法

## 7. 响应场景与条件匹配

### 7.1 场景结构

每个接口包含多条条件场景和恰好一条默认场景。默认场景不能删除和停用，条件场景可单独启停。

| 字段 | 约束 |
| --- | --- |
| 名称 | 必填，1～50 字符 |
| 类型 | 条件场景或默认场景 |
| 启用状态 | 默认启用；默认场景固定启用 |
| 优先级 | 条件场景为 1～9999 整数，同接口内不可重复，包括停用场景 |
| 条件字段 | 条件场景必填，默认场景无条件 |
| 运算符 | 等于、不等于、包含、存在、不存在 |
| 目标值 | 等于/不等于/包含时必填，允许明确填写空字符串 |
| 响应模式 | 原样报文或 JavaScript |
| 响应设置 | 状态码、响应头、Content-Type、延迟、正文或脚本 |

条件场景按优先级从大到小排序，第一条命中即停止。停用场景跳过，其他场景未命中时使用默认场景。命中场景脚本报错时返回错误，不再尝试下一场景或默认场景。

### 7.2 条件字段

首版每条场景支持一个条件，不提供多条件组合。

| 示例 | 含义 |
| --- | --- |
| `body.orderId` | JSON Body 顶层订单号 |
| `body.data.orderId` | JSON 嵌套字段 |
| `body.items.0.code` | JSON 数组第一项的 code |
| `query.orderId` | Query 参数 |
| `headers.x-scene` | 请求头，配置名称统一小写 |
| `pathParams.orderId` | URL 路径参数 |

以点分隔访问普通对象属性，数字段访问数组下标，不执行表达式，不遍历原型链。包含点的原始字段名不使用本简写匹配，可在脚本中通过方括号访问。

### 7.3 比较语义

为贴近已认可原型，目标值使用文本输入。标量字符串、数字和布尔值转为文本进行区分大小写的精确比较，不自动去除前后空格。数字 `1001` 与字符串 `"1001"` 均匹配目标文本 `1001`；字符串 `"001001"` 不匹配。

| 运算符 | 定义 |
| --- | --- |
| 等于 | 字段存在且非 null，为标量时转换成文本后与目标值完全一致 |
| 不等于 | 字段存在且非 null，为标量时转换成文本后与目标值不同 |
| 包含 | 字段存在且为标量，转换成文本后包含目标文本 |
| 存在 | 对象具有该字段，即使字段值为 null 或空字符串 |
| 不存在 | 对象中不存在该字段 |

数组和对象只支持存在/不存在，不隐式 stringify 后比较；需要判断重复 Query 参数或复杂结构时使用脚本。缺失值不命中“不等于”，防止请求缺参误命中业务场景。目标为空字符串时，“包含”按普通字符串包含规则处理，界面提示其会匹配所有非 null 标量。

## 8. 响应配置

### 8.1 公共设置

| 设置 | 需求 |
| --- | --- |
| HTTP 状态码 | 默认 200，允许整数 200～599；不支持 1xx 和协议切换 |
| Content-Type | 默认 `application/json; charset=utf-8`，预置 JSON/XML/纯文本/HTML，允许合法自定义文本媒体类型 |
| 自定义响应头 | 键值表单，Header 名大小写不敏感，不允许重复名称 |
| 响应延迟 | 非负整数毫秒，默认 0，默认最大 10000，由部署配置限定 |
| 正文大小 | 默认最大 2 MiB，按实际 UTF-8 编码字节数检查 |

Content-Type 单独展示，不允许在响应头表格重复添加。可配置 Location 等合法业务头。拒绝非法名称、CR/LF 值以及 Host、Content-Length、Transfer-Encoding、Connection、Upgrade、Keep-Alive、Trailer、TE 等由协议栈管理或不支持的头。首版不支持重复响应头，包括多个 Set-Cookie。

平台默认不自动添加允许任意来源的 CORS 配置；有浏览器联调需要时，使用者显式设置相应响应头和 OPTIONS 接口。后端服务器调用不依赖浏览器 CORS。

### 8.2 原样报文

- 正文以 UTF-8 文本保存和返回，支持 JSON、XML、文本和 HTML
- 保留保存后的空格、缩进、换行和字段顺序，不在返回前格式化或解析重写
- “原样”指保存文本的 UTF-8 内容，不承诺恢复剪贴板粘贴前的原始文件字节或不同换行编码
- 不进行模板变量替换，不执行正文中的脚本，不套统一业务响应
- JSON 格式化为用户主动操作；非法 JSON 可以作为原样报文保存和发布，用于测试调用方解析失败
- 用户主动选择格式化时，非法 JSON 应提示失败且保留原文
- 允许空正文；状态码为 204 或 304 时必须为空，否则发布校验失败
- HEAD 即使配置正文也不向调用方发送正文，调试结果显示“按 HEAD 语义省略正文”

### 8.3 JavaScript 响应

用户定义固定入口：

```javascript
function main(request, mock) {
  return {
    status: 200,
    body: {
      code: "0000",
      data: request.body,
      requestId: mock.uuid()
    }
  };
}
```

平台负责调用入口，不要求用户手动调用 `main()`。`status`、`headers`、`body` 是响应描述，不作为整体 JSON 返回。

请求 `{"orderId":"1001"}` 时，上例响应正文为：

```json
{
  "code": "0000",
  "data": { "orderId": "1001" },
  "requestId": "本次调用生成的 UUID"
}
```

用户应能通过脚本表达判断、循环、数组转换、字符串处理和 JSON 处理；引擎支持的 JavaScript 语法范围在技术方案中锁定并在帮助页说明。首版不开放 `require`、`import`、npm 包、fetch、定时器和异步入口。

## 9. JavaScript 执行契约

### 9.1 request 对象

| 字段 | 类型与语义 |
| --- | --- |
| method | 大写 HTTP 方法 |
| path | 去掉 `/m/{systemKey}` 后的请求路径，不含 Query；保留编码形式 |
| pathParams | 路由参数对象，值为解码一次后的字符串 |
| query | Query 对象，单值为字符串，重复键为字符串数组 |
| headers | 名称统一小写的请求头对象，单值为字符串；框架可保留的重复值为数组 |
| body | 解析后的 JSON 值或 URL 编码表单对象；其他文本类型和空请求为 null |
| rawBody | 解码后的原始 UTF-8 请求正文字符串，空正文为 `""` |

请求对象只包含可序列化数据，不暴露 Servlet、数据库连接或 Java 宿主对象。每次请求都提供独立副本，脚本即使修改该副本，也不能影响其他请求或已保存配置。

解析规则：

- `application/json` 和 `application/*+json` 的非空正文解析为 JSON；格式错误返回 400，不执行规则或脚本
- JSON 顶层可为对象、数组、字符串、数字、布尔或 null；路径条件只在可访问字段上匹配
- `application/x-www-form-urlencoded` 解析到 body；重复键使用数组
- XML、纯文本、HTML 或未声明类型的正文通过 rawBody 读取，body 为 null
- UTF-8 为唯一支持的请求文本编码；不支持的显式字符集、multipart 和二进制媒体类型返回 415
- 大小限制在解析前检查，包括分块输入；超限返回 413
- 不因名为 Host 或 X-Forwarded-For 的请求头改变平台配置或信任边界

### 9.2 mock 工具对象

| 方法 | 定义 |
| --- | --- |
| `mock.uuid()` | 每次调用生成 UUID v4 字符串 |
| `mock.now()` | 当前时间的 UTC ISO 8601 字符串，例如 `2026-10-19T08:00:00.000Z` |
| `mock.randomInt(min, max)` | 返回包含两端的随机整数；参数必须为安全整数且 min ≤ max，否则脚本报错 |

内置随机能力用于测试造数，不作为安全令牌或认证密钥生成器。无需保证不同请求的随机数互不重复。

### 9.3 返回对象

```javascript
return {
  status: 201,
  headers: {
    "Content-Type": "application/json; charset=utf-8",
    "X-Mock-Scene": "created"
  },
  body: {
    code: "0000",
    message: "创建成功"
  }
};
```

| 项目 | 约定 |
| --- | --- |
| 顶层 | 必须为普通对象，不能为数组、null、Promise 或标量 |
| status | 可省略，省略时采用场景状态码；填写时须为 200～599 整数 |
| headers | 可省略；普通对象，值为字符串，大小写不敏感覆盖场景响应头 |
| body | 必须存在；允许 JSON 可表示值和字符串 |
| 未知顶层字段 | 返回契约错误，避免拼写错误被静默忽略 |
| delay | 不属于脚本返回字段，统一在场景设置中配置 |

序列化约定：

- 字符串正文直接写出，不增加 JSON 引号
- 对象、数组、数字、布尔值和 null 按 JSON 序列化；null 返回文本 `null`
- 空字符串表示零字节正文，区别于 null
- 拒绝 undefined、函数、Symbol、BigInt、非有限数值、循环引用和不可支持的宿主对象，不静默丢字段
- JSON 序列化只执行一次，不产生转义后的二次 JSON 字符串
- 最终 Content-Type 以脚本覆盖值优先，其次使用场景配置；不根据正文猜测或重写
- 状态码 204/304 时，脚本 body 只能为空字符串，否则视为返回契约错误
- HEAD 按相同逻辑校验脚本结果，但最终不输出正文
- 脚本返回头同样执行第 8.1 节校验，不能绕过协议限制

### 9.4 超时与隔离

- 用户脚本不得在管理应用的主 JVM 内执行
- 实际执行环境须与管理服务进程隔离，禁止访问文件、网络、数据库、环境密钥、系统命令和宿主 Java 类
- 不提供跨请求共享变量、文件存储或持久上下文
- 默认执行墙钟上限为 1000ms，覆盖脚本运行及结果处理；开始执行后计时，排队和人工延迟另行计时
- 超时由执行环境外部监督机制终止，不仅依赖线程中断
- 为执行环境配置 CPU、内存、并发与等待队列上限；实现方式由部署技术方案确定
- 工作进程崩溃、内存耗尽或被终止后能够回收补充，不影响原样响应接口
- 前端调试与真实调用使用同一服务端执行实现，浏览器不能作为正式脚本执行器
- 语法检查在发布时进行，但不执行用户脚本；运行结果依赖请求数据，仍须在每次调用时校验

## 10. 在线调试

### 10.1 输入

调试来源提供“当前编辑内容”和“已发布版本”。前者允许未保存内容，后者只使用服务端当前发布快照，不受页面内容影响。

- 请求方法可修改，以验证方法错误
- 请求路径填写参数替换后的实际路径，不包含平台系统前缀
- Query、Header 提供键值输入；重复键可重复添加
- Body 支持 JSON、表单、原始文本和无正文，配合 Content-Type 使用
- 请求编码与实际入口一致，不能直接把客户端任意对象当作可信运行上下文
- 不支持在调试页面填任意外部 URL 发起代理请求

### 10.2 调试执行

调试入口定位当前接口或其草稿，使用与真实入口相同的请求解析、路径匹配、条件匹配、响应生成和错误映射逻辑。已发布版本调试读取服务器快照；未发布接口不能选择该来源。

当前编辑内容调试按页面配置进行，不修改数据库、不隐式发布。可调试草稿启用状态，停用草稿返回 404。系统总开关停用时允许当前编辑内容调试，但界面明确提示真实调用不可用；已发布来源遵循总开关。

### 10.3 输出

结果区域至少显示：

- 来源和实际使用的发布版本或草稿修订号
- HTTP 状态码、响应头、正文
- 命中场景及其优先级，未命中时说明原因
- 总耗时、排队耗时、脚本耗时、配置延迟
- 平台追踪编号，便于查询日志
- 平台错误类型和安全的诊断信息，区分配置返回的业务失败与平台执行失败

显示的总耗时为服务端观测值，浏览器网络往返时间可单独展示，不混为脚本执行耗时。用户取消等待不等于服务端执行已立即终止；服务端仍执行自身超时与清理机制。

## 11. 草稿、发布与回滚

### 11.1 状态和生效时机

| 操作 | 影响草稿 | 影响新真实调用 |
| --- | --- | --- |
| 编辑未保存 | 仅浏览器当前编辑内容 | 无影响 |
| 保存草稿 | 更新服务端草稿及修订号 | 无影响 |
| 修改接口启停并保存 | 修改草稿 | 无影响，发布后才生效 |
| 发布接口 | 从确认的草稿生成新快照 | 原子切换到新快照 |
| 回滚 | 保持当前草稿 | 历史快照生成新版本后原子切换 |
| 系统停用 | 不改接口草稿 | 总开关立即停止新请求 |
| 接口或系统归档 | 保留配置和历史 | 立即停止新请求 |

### 11.2 发布流程

1. 有未保存修改时，提示此次发布包含当前编辑内容
2. 服务端检查草稿修订号，存在并发更新则拒绝覆盖
3. 校验系统、路由、默认场景、条件字段、优先级、响应设置、大小限制和脚本语法
4. 将本次配置保存为草稿，并创建包含全部规则的不可变发布快照
5. 在同一事务内切换当前发布版本，失败时全部回滚
6. 完成运行配置更新后返回成功，前端显示版本和生效地址

发布确认返回后到达的新请求必须使用新版本。发布前已经开始的请求使用其开始时捕获的完整快照，不混用新旧规则。单机首版不允许长时间缓存旧版本而显示“发布成功”。

### 11.3 回滚

- 回滚从指定历史快照复制配置，重新校验当前路由冲突和平台限制
- 校验成功后创建新版本，例如 v5 回滚到 v2 的内容，生成 v6，而非修改 v2
- 记录来源版本，不删除中间历史
- 当前草稿保持不变，页面提示草稿与发布内容可能不同
- 历史路径被其他接口占用、系统已归档或原配置不再满足限制时，回滚失败并说明原因
- 发布历史首版不提供手动删除，容量作为运维监控项，不无限制复制日志正文到历史中

### 11.4 并发修改

即使没有用户体系，也必须防止两位使用者互相覆盖。

- 草稿保存、发布和回滚携带预期修订号/版本号
- 版本不一致返回 409，保留本地编辑内容，提示重新加载或复制内容后处理
- 不使用“最后写入覆盖”作为默认行为
- 未登录情况下记录时间、操作类型和可信来源地址，操作人显示“未认证”，不伪造域账号或用户身份

## 12. 真实请求处理与错误规范

### 12.1 执行链路

```text
内网 HTTP 请求
  → 大小和基础协议检查
  → 系统及路由匹配
  → 捕获当前发布版本
  → 请求正文解析
  → 按优先级匹配场景
  → 原样响应 / 脚本执行
  → 响应校验与人工延迟
  → 返回 HTTP 响应
  → 异步记录调用摘要
```

人工延迟在响应校验成功后执行，不占用脚本执行工作进程。平台错误不再附加场景延迟。延迟等待数量同样有上限，避免大量慢响应占满内存。

### 12.2 错误映射

| HTTP 状态 | 平台错误码 | 情况 |
| --- | --- | --- |
| 400 | INVALID_REQUEST | 非法路径编码、声明 JSON 但正文非法等 |
| 404 | MOCK_NOT_FOUND | 系统/接口不存在、停用、归档或未发布 |
| 405 | METHOD_NOT_ALLOWED | 路径可用但请求方法未配置 |
| 413 | REQUEST_TOO_LARGE | 请求正文超限 |
| 415 | UNSUPPORTED_MEDIA_TYPE | 不支持的正文媒体类型或字符集 |
| 500 | SCRIPT_EXECUTION_ERROR | 脚本抛错或执行进程异常终止 |
| 500 | INVALID_SCRIPT_RESPONSE | 返回对象、响应头或序列化内容不符合约定 |
| 500 | RESPONSE_TOO_LARGE | 输出正文超限 |
| 503 | SCRIPT_CAPACITY_EXCEEDED | 脚本排队容量或等待时间超限 |
| 503 | MOCK_SERVICE_UNAVAILABLE | 平台依赖或执行服务不可用 |
| 504 | SCRIPT_TIMEOUT | 脚本执行超时 |

平台错误统一使用如下结构，业务配置的响应不采用此包装：

```json
{
  "error": {
    "code": "SCRIPT_TIMEOUT",
    "message": "脚本执行超时",
    "traceId": "本次调用追踪编号"
  }
}
```

HEAD 请求的平台错误同样不发送正文。对外错误不包含源代码、数据库信息、宿主路径或调用堆栈。平台产生的错误使用独立错误标记头以便辨识；业务配置不得覆盖该保留头。正常业务响应不强制注入追踪正文或业务头。

用户主动配置的 HTTP 500 是有效 Mock 响应，应标记“配置响应”；脚本执行失败导致的 500 标记“平台错误”，两者在日志和调试结果中区分。

## 13. 日志与可观测性

### 13.1 调用记录

真实调用与在线调试共用日志入口，通过来源筛选区分。日志列表支持系统、接口、时间范围、HTTP 状态、场景及平台错误码筛选，默认按时间倒序，每页默认 20 条，最多 100 条。

| 字段 | 说明 |
| --- | --- |
| 追踪编号 | 平台生成，用于关联处理过程 |
| 请求时间 | 服务端时间，保存统一时间基准，界面按部署时区展示 |
| 来源 | 真实调用 / 草稿调试 / 发布版本调试 |
| 系统与接口 | 显示名称、方法和路径 |
| 配置版本 | 发布版本或草稿修订号，不可事后用最新配置替代 |
| 命中场景 | 场景名称和优先级，默认场景单独标识 |
| 结果 | 状态码、配置响应/平台错误及错误码 |
| 耗时 | 总耗时、队列等待、脚本执行、人工延迟 |
| 数据量 | 请求和响应字节数 |
| 来源地址 | 服务端观测或可信代理提供的地址 |

默认只记录摘要，不保存完整正文、完整 Query 和完整请求头。通过部署配置开启诊断正文记录时，必须执行脱敏和截断，界面显式标识“已截断”。

### 13.2 脱敏与容量

- Authorization、Cookie、Set-Cookie、密码、token、secret 等字段默认脱敏，字段名称大小写不敏感
- JSON 支持按配置的字段名/路径递归脱敏；无法可靠解析或脱敏的原始文本正文默认不记录
- Query 中敏感字段脱敏；路径参数可能含业务标识，建议模板摘要优先并支持日志关闭
- 诊断正文默认每个请求/响应最多记录 4 KiB，原始请求及响应不因日志截断而改变
- 默认保留 7 天，建议首版另设最多 100 万条摘要的总量上限，均由部署配置控制
- 清理按固定批次执行，优先清理超期数据，超总量时清理最早记录
- 异步日志队列有界，队列满或落库失败不阻塞 Mock 响应，记录丢弃计数和运维告警
- 页面不得将有条件、可能丢弃的调用日志描述为完整审计证明

### 13.3 操作记录与健康检查

记录系统启停/归档、接口归档、发布、回滚、冲突失败等关键事件。无用户体系时不提供实名操作人归属。

提供存活、数据库就绪、脚本执行服务状态、队列长度、超时次数和日志丢弃数量等基础运维信息。脚本服务故障显示降级状态，原样报文接口继续工作；数据库不可用时未能取得可靠配置的请求明确返回 503，不隐式使用不受控的陈旧配置。

## 14. 数据与实现约束

### 14.1 逻辑数据模型

| 对象 | 主要数据 | 约束 |
| --- | --- | --- |
| 第三方系统 | 名称、标识、说明、启停、归档、创建/修改时间 | 标识唯一且不可修改 |
| 接口 | 系统、草稿配置、草稿修订号、当前版本指针、归档状态 | 路由冲突受控 |
| 响应场景 | 名称、条件、优先级、启用、响应配置 | 隶属接口草稿；默认场景唯一 |
| 发布快照 | 完整接口配置、版本、时间、发布类型、回滚来源 | 不可变 |
| 调用记录 | 请求摘要、配置版本、响应结果、耗时、错误 | 按期限及容量清理 |
| 操作记录 | 对象、时间、操作、结果、来源 | 不依赖用户表 |

场景可独立存表或作为受控结构存储；最终表结构和索引由技术设计确定。接口配置和响应脚本属于业务数据，必须持久化，不能仅保存在 JVM 内存、浏览器或应用临时目录。

### 14.2 后端边界

- 管理接口负责配置、调试、发布和查询，可采用统一管理响应对象
- Mock 入口直接输出用户配置的状态码、响应头和正文
- Controller 负责接参、校验、调用服务和响应，不承载数据库条件或业务编排
- 各表 Service 管理自身数据访问，跨表事务由业务编排服务处理
- 发布、回滚和多步骤配置写入具有一致的事务边界
- 业务查询批量处理，避免逐条查询和逐条数据库写入
- Java 项目沿用用户通用编码规范；pack-mom 专属工具类及 EnableDto 强制复用要求，在本独立项目按用户最新指示排除
- 使用公共依赖前核对用途、版本和 API；不复制 pack-mom 源码或引入整套业务依赖

### 14.3 部署形态原则

业务后端采用单体，不引入注册中心、配置中心、消息队列等微服务配套。脚本执行隔离是必要运行边界，不代表业务服务拆成微服务。

建议使用前端静态资源、Java/Spring Boot 后端、MySQL 和独立脚本执行环境。具体 JDK、Spring Boot、脚本引擎和数据库版本在技术设计阶段锁定，不能把本需求文档中的建议视为已经完成兼容性验证。

## 15. 非功能需求与部署交付

### 15.1 内网与安全边界

- 部署后所有常规功能在断开公网时可用，包括编辑器、字体、脚本工具和帮助页
- 静态资源随安装包提供，不加载公网 CDN
- 管理入口与 Mock 入口可使用不同域名或端口，管理入口仅向受信内网人员所在网段开放
- 首版不做域登录、账号或调用密钥；“内网部署”不等同于身份认证，需要在运维说明中明确可访问者拥有管理能力
- 调用入口不允许任意脚本访问外网、内网服务或主机资源
- 数据库和内部执行服务不直接暴露给业务调用方，秘密配置不进入脚本上下文
- 管理页面防止用户报文造成 HTML 注入；响应头、路径和条件均进行输入校验

### 15.2 建议默认资源限制

以下为首版建议值，可部署配置调整，实际有效上限须在帮助页显示。

| 项目 | 默认建议 |
| --- | --- |
| 请求正文 | 1 MiB |
| 响应正文 | 2 MiB |
| 单脚本源代码 | 64 KiB |
| 单接口场景数 | 50，包含默认场景 |
| 响应头 | 最多 32 项，名称和值合计不超过 16 KiB |
| 脚本执行墙钟上限 | 1000ms |
| 脚本并发 | 4 |
| 脚本等待队列 | 100 |
| 最大排队等待 | 1000ms |
| 人工响应延迟 | 0～10000ms |
| 延迟等待请求总数 | 200，超限返回 503 |
| 单个执行工作环境内存 | 初始建议 256 MiB，须经所选引擎验证后锁定，不承诺一定适用 |
| 诊断正文记录 | 默认关闭，开启后每个方向最多 4 KiB |
| 调用摘要保留 | 7 天且最多 100 万条 |

MiB、KiB 分别为 1024² 和 1024 字节。限额必须在服务端执行，不能只依赖页面输入限制。

### 15.3 性能验证目标

当前未确认服务器规格，以下作为拟定压测基线，不是已经测得的性能结论：

- 在至少 4 核、8 GiB、局域网、预热完成、无人工延迟、1 KiB 正文、单实例环境下验证
- 原样响应：100 并发，持续 10 分钟，目标吞吐不低于 100 请求/秒，p95 服务端耗时不超过 100ms
- 简单脚本：4 并发，持续 10 分钟，目标吞吐不低于 10 请求/秒，p95 总耗时不超过 500ms，不包括人为延迟和首次冷启动
- 正常负载下平台错误率小于 0.1%；刻意配置的业务错误状态不计为平台故障
- 超限负载可受控拒绝，不崩溃、不持续增长队列；死循环任务终止后资源能够恢复
- 正式性能验收前，根据实际部署环境确认指标；未达标时提供原因和可调整方案，不隐瞒脚本隔离带来的开销

### 15.4 部署和运维交付

正式开发交付应包含：

1. 完整源码、构建命令和锁定依赖版本
2. 配置项说明、环境变量示例和默认值
3. 数据库初始化及后续升级脚本
4. 选定环境的安装部署教程，包含内网地址、端口和健康检查
5. 离线安装包或镜像准备、传入内网和启动步骤
6. 无公网条件下的完整功能验证步骤
7. 数据库及必要配置的备份、恢复和恢复验证步骤
8. 应用升级、数据库迁移及失败回退说明；不承诺所有数据库变更都能简单回退
9. 日志定位、脚本执行服务恢复、磁盘容量和保留策略说明
10. curl 或等效 HTTP 调用样例，覆盖静态、脚本、错误和延迟场景

备份至少覆盖系统、接口、场景、发布历史及部署配置；调用记录可按运维策略选择是否备份。密钥配置与普通配置分开处理。
