# MockLab 开发说明与 API

## 1. 技术与版本

| 组件 | 版本/选择 |
| --- | --- |
| Java | 21 |
| Spring Boot | 3.5.7 |
| MyBatis-Plus | 3.5.12 |
| GraalJS / Polyglot | 24.2.2 Community |
| Vue | 3.5.22 |
| Vite | 7.1.12 |
| 开发数据库 | MySQL 5.7 / 8.x，默认本机 3306/mocklab |
| 部署数据库 | 现有 MySQL 5.7，JDBC 驱动锁定为 8.0.33 |
| 网关 | 复用现有 Nginx，业务 Compose 不部署网关容器 |

依赖锁定以 Maven POM 与前端 package-lock.json 为准。没有使用 pack-mom 业务依赖；集合工具使用 Spring 公共工具，通用 CRUD 使用 MyBatis-Plus。

## 前端地址配置

前端通过 VITE_BACKEND_URL 统一确定管理请求与可复制 Mock 链接的后端入口。开发模式由 frontend/.env.development 提供后端地址，Vite 的 /api、/m、/actuator 代理读取同一配置，浏览器请求经过同源代理，复制链接指向配置的后端。

生产模式读取 frontend/.env.production，默认留空并使用 window.location.origin，适配现有 Nginx 同时代理页面和后端接口的部署方式。需要固定入口时在构建前填写该配置。后端 MockProperties 和 /api/settings 不再提供 baseUrl 字段。

## 2. 请求链路

```text
HTTP /m/{systemKey}/**
  -> MockController
  -> DispatchService
  -> SystemService + EndpointService：捕获已发布快照
  -> RouteMatcher / RequestParser / SceneMatcher
  -> ResponseEngine
      -> 原样正文
      -> RunnerClient -> Unix Socket -> 独立 Supervisor -> GraalJS 工作进程
  -> DelayScheduler：不占用工作进程的异步延迟
  -> HTTP 状态、响应头、原样正文
  -> LogWriter：有界异步摘要队列
```

开发模式使用回环 TCP 9091，Linux Docker 使用 Unix Socket。执行容器 `network_mode: none`，后端不持有 Docker Socket 或执行容器管理权限。

## 3. 数据与事务

- mock_system：系统标识、名称、状态、修订号
- mock_endpoint：草稿 JSON、发布 JSON、修订号、发布版本、归档状态
- mock_version：接口完整不可变发布快照
- mock_call_log：调用摘要及可选诊断信息
- mock_operation：配置关键操作记录

发布、回滚、接口写入由 ConfigurationService 编排事务。通过锁定系统行串行化同命名空间的路由变更，再以接口 revision 检查陈旧写入；数据库隔离级别使用 READ_COMMITTED。真实调用每次查询数据库，不存在发布后旧缓存持续生效的问题。

归档恢复接口时清空发布指针，但保留历史版本编号。恢复后必须重新发布；回滚建立新版本，保持当前草稿。发布字段允许明确写入 null，避免 ORM 的非空更新策略误保留旧发布状态。

## 4. 管理 API

所有写 API 使用 JSON，并带 `X-MockLab-Request: 1`。该头用于阻止浏览器跨站简单表单提交，不是身份认证或访问密钥。

| 方法 | 地址 | 含义 |
| --- | --- | --- |
| GET | /api/settings | 展示有效运行配置，不包含数据库密码 |
| GET | /api/systems?archived=false | 查询系统 |
| POST | /api/systems | 创建或更新系统实体，更新携带 id/revision |
| GET | /api/systems/{id}/endpoints | 查询接口实体及解析后的配置 |
| POST | /api/endpoints | 创建接口，提交 systemId 与 draft |
| GET | /api/endpoints/{id} | 查询接口 |
| PUT | /api/endpoints/{id}/draft | 保存草稿，提交 revision、config |
| POST | /api/endpoints/{id}/publish | 发布当前提交配置，提交 revision、config |
| POST | /api/endpoints/{id}/rollback | 提交 revision、expectedVersion、version |
| POST | /api/endpoints/{id}/lifecycle | 提交 revision、archived |
| GET | /api/endpoints/{id}/versions | 查询版本与完整快照 |
| POST | /api/endpoints/{id}/debug | 服务端调试 |
| GET | /api/logs | 调用日志分页 |
| GET | /api/logs/{id} | 日志详情 |
| GET | /api/operations | 最近一百条关键操作 |
| GET | /actuator/health | 数据库、执行服务等综合健康状态 |
| GET | /actuator/metrics | 运维指标，仅管理入口提供 |

当前编辑内容调试使用 source=draft，并传入完整 config 对象；其结构可以参考 GET /api/endpoints/{id} 返回的 draft。

日志筛选：systemId、endpointId、source、status、errorCode、scene、requestPath、from、to。分页参数 current、size，size 限制 1～100。时间使用 UTC ISO 字符串；页面会将本地选择的时间转换成 UTC。

调试体：

```json
{
  "source": "published",
  "revision": 1,
  "config": null,
  "method": "POST",
  "path": "/api/orders/query",
  "query": "tag=a&tag=b",
  "headers": {"Content-Type":"application/json"},
  "rawBody": "{\"orderId\":\"1001\"}"
}
```

## 5. 响应与规则契约

- 场景列表位于 config.rules，场景 id 只用于配置内定位
- default=true 的场景恰好一个，必须启用
- 条件场景 priority 为 1～9999，同接口内不能重复
- operator 为 eq / ne / contains / exists / missing
- 条件路径支持 body、query、headers、pathParams；数组下标使用点分数字
- 缺失字段不命中 ne；null 与空字符串区别处理
- mode 为 raw 或 script；code 为保存的报文或脚本
- headers 中不允许重复或单独设置 Content-Type，Content-Type 使用 contentType 字段
- 所有字段和正文都在服务器再次验证，不能依靠前端限制

管理错误返回 `{error:{code,message}}`。Mock 平台错误返回 `{error:{code,message,traceId}}` 并设置 `X-Mock-Platform-Error`，合法的用户业务响应不添加统一包装。

## 6. 脚本隔离及限制

GraalJS 支持 ECMAScript 2023。每次调用创建独立 Context，关闭宿主访问、文件/Socket IO、环境变量、进程、线程和 native access；输入输出流与监督协议隔离。没有 Node.js 全局对象或 npm 依赖。

每个工作进程独立 JVM，堆上限 96 MiB、Metaspace 上限 128 MiB、代码缓存上限 32 MiB。这些是 JVM 区域上限，不等于进程 RSS 总上限；Compose 对整个执行容器另设 2 GiB 内存、2 CPU 和 128 进程限制。

监督进程最多 4 个脚本同时运行，最多 100 个额外等待，队列等待最多 1000ms，执行墙钟最多 1000ms。超时强制终止工作进程并异步补充；工作进程异常退出或堆耗尽为受控错误。响应延迟在后端定时调度器完成，最多等待 200 个请求。

本实现使用进程、容器边界和受限上下文，不声称启用了 GraalVM 的 UNTRUSTED isolate policy。官方说明参考：

- [Docker 无网络驱动](https://docs.docker.com/engine/network/drivers/none/)
- [GraalVM 沙箱策略说明](https://www.graalvm.org/latest/security-guide/sandboxing/)

## 7. 日志边界

默认只记录摘要，完整正文关闭。LOG_BODY=true 时，对 JSON 中 authorization、cookie、password、token、secret、apiKey 等字段递归脱敏，非 JSON 响应正文不记录，每方向默认最多截取 4 KiB 并附截断提示。

日志失败或队列满不阻塞正常响应。可通过 mocklab.logs.queue、mocklab.logs.dropped 指标观察。日志按 7 天和 100 万条上限每分钟分批清理，每批最多 1000 条，超量清理需要多个周期，不代表硬性精确行数封顶。

来源地址为后端实际观测地址；经过 Nginx 时默认是网关地址，不信任任意客户端 X-Forwarded-For。没有实名用户，因此操作记录不构成实名审计。

## 8. 后续变更

初始 schema.sql 使用 CREATE TABLE IF NOT EXISTS，仅负责新环境初始化。后续发布若改表结构，必须提供明确迁移脚本，不能依赖本初始脚本自动更新已有字段。首次生产部署前在 Linux 上完成 MySQL、Unix Socket、容器资源与备份恢复验收。
